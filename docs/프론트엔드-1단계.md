# 프론트엔드 1단계 구현 기록

## 범위

`prototype/index.html`을 시각 비교 기준으로 보존하면서 Vite + React + TypeScript 애플리케이션으로 이전했다. 이 단계는 가짜 팀원 데이터와 브라우저 로컬 상태만 사용하며 Supabase, RPC, 관리자 인증은 포함하지 않는다.

## 구조

- `src/app`: 애플리케이션 진입점과 현재의 얇은 경로 분기
- `src/pages`: `/` 현황판 페이지와 `/admin` 페이지 경계
- `src/features`: 입장 및 현황판 기능과 기능 전용 컴포넌트
- `src/shared/ui`: 랜섬 문자, 비즈, 아이콘처럼 도메인에 무관한 작은 UI
- `src/domain`: 상태 타입, 계획/위치 토글 규칙, KST 날짜 계산
- `src/data`: 현황판 데이터 접근 인터페이스와 가짜 저장소
- `src/storage`: 날짜별 로컬 입장 상태 직렬화와 만료 처리
- `src/hooks`: UI, 데이터 접근, 저장 상태를 연결하는 애플리케이션 상태
- `src/styles`: 프로토타입에서 이전한 전역 스타일
- `public/assets`, `public/fonts`: 프로토타입에서 사용하는 이미지와 로컬 마커 폰트

## 보존한 동작

- 공백이 아닌 모든 이름의 입장
- 같은 브라우저의 당일 이름과 상태 복원
- KST 날짜 변경 시 로컬 상태 초기화
- `Riding today` 독립 토글
- `In the club room` / `Out riding` 상호 배타 토글
- 본인 스티커의 `×`로 해당 상태만 해제
- 이름 입력 화면으로 이동한 뒤 다시 현황판에 들어오는 흐름
- `prefers-reduced-motion`에서 전환과 애니메이션 제거
- 기존 접근성 레이블, 라이브 상태 안내, 44px 터치 영역

## 시각 검증

- 원본과 React 화면을 동일한 브라우저에서 데스크톱 기본 뷰로 비교
- 360 × 800 뷰포트에서 모바일 상단, 조작 카드, 첫 상태 메모지를 비교
- 360px에서 문서 너비와 스크롤 너비가 모두 360px임을 확인
- 로드된 이미지 중 깨진 에셋이 없고 브라우저 오류 로그가 없음을 확인

## 다음 단계 교체 지점

`BoardRepository`의 `MockBoardRepository`를 Supabase RPC 구현으로 교체한다. `useBoardApp`의 상태 변경 함수는 이후 `register`, `set_planned`, `set_location`, `get_board` 호출과 요청 순서/오류 복구를 연결하는 지점이다. `/admin` 자리표시자는 관리자 라우트와 세션 인증 UI로 교체한다. `DailyEntry`의 `clientNonce`와 `memberId` 필드는 서버 등록 멱등성과 오늘 입장자 식별을 위해 이미 마련돼 있다.
